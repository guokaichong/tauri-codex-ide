## 1. 架构与构建策略

- **本地端**只做 GUI、文件读写、终端白名单（git/cargo/npm/pip）、API 转发，不跑模型推理。
- **AI 算力**全部走国内云端 OpenAI 兼容 API（火山方舟三通道 / MiniMax / DeepSeek），可降级本地 Ollama。详见 README「AI 模型接入」。
- **打包在云端**：Tauri 的 Windows 安装包依赖 MSVC + WebView2 + NSIS，**必须在 Windows 环境构建**；本机 N95 低配且无 Rust 工具链，因此统一交给 GitHub Actions 的免费 `windows-latest`  runner（实测一次约 8 分钟）。
- **为什么不用 Gitee 云端**：
  - Gitee Go 免费版云端构建机只有 Linux（Maven/Gradle/Node/Python/Go/GCC 镜像），**没有 Windows 资源池**，无法产出 Tauri Windows EXE；
  - 本仓库早先的 `.workflow/build.yml` 被 Gitee Go 判为「配置结构错误 stages[0].steps」，从未运行；
  - `.gitee/workflows/`（Gitee Actions）属企业付费功能，页面 404 未开通。
  - 以上两份文件已于 2026-09-22 删除，Gitee 仅作代码镜像。

## 3. Git 操作约定（PowerShell 5.1）

### 3.1 每条 git 命令前置 PATH

便携 Git 不在系统 PATH，**新开终端窗口后**先执行：

```powershell
$env:Path='E:\Tools\MinGit\cmd;'+$env:Path
```

### 3.2 提交身份内联传入（不要改全局配置）

```powershell
git -c user.name='guokaichong' -c user.email='2214866337@qq.com' commit -m '提交说明'
git -c user.name='guokaichong' -c user.email='2214866337@qq.com' tag -a v0.1.0 -m 'TauriCodexIDE v0.1.0'
```

### 3.3 双远端

```text
origin  → https://gitee.com/guokaichong/tauri-codex-ide.git   （镜像）
github  → https://github.com/guokaichong/tauri-codex-ide.git  （构建主力）
```

添加方式（已配好，换机时参考）：

```powershell
git remote add origin https://gitee.com/guokaichong/tauri-codex-ide.git
git remote add github https://github.com/guokaichong/tauri-codex-ide.git
```

### 3.4 凭据

| 平台 | 认证方式 | 保存位置 |
| --- | --- | --- |
| GitHub | GCM（Git Credential Manager）OAuth 浏览器授权，点「Sign in with your browser」 | Windows 凭据管理器，一次授权长期有效 |
| Gitee | 用户名 `guokaichong` + **私人访问令牌**（不是登录密码、不是邮箱） | 未保存；推送时一次性带在 URL 中 |

Gitee 推送（令牌替换成自己的，**不要**把令牌写进 remote 配置或任何文件）：

```powershell
git push https://guokaichong:<你的Gitee私人令牌>@gitee.com/guokaichong/tauri-codex-ide.git main
```

令牌有效性可用 OpenAPI 自检（返回 200 即有效）：

```powershell
Invoke-WebRequest "https://gitee.com/api/v5/user?access_token=<令牌>" -UseBasicParsing
```

Gitee 令牌申请位置：Gitee → 设置 → 安全设置 → 私人令牌（勾 `projects` 权限即可）。

## 4. 云端构建（GitHub Actions）

### 4.1 流水线定义

文件：`.github/workflows/release-windows.yml`

- 触发：推送 `v*` 标签（也支持 Actions 页手动 `workflow_dispatch`）；**推 main 不触发**
- Runner：`windows-latest`（免费，公开仓库不计费）
- 步骤：checkout → Node(lts) + npm 缓存 → Rust stable + cargo 缓存 → `npm ci` → `tauri-apps/tauri-action@v0`
- 结果：自动创建同名 GitHub Release，并上传 NSIS 安装包
- Release 名：`TauriCodexIDE v__VERSION__`；产物例：`TauriCodexIDE_0.1.0_x64-setup.exe`（约 2.4 MB）

### 4.2 命令行查构建状态（api.github.com 国内稳定，无需认证，公开仓库）

```powershell
$H = @{ 'User-Agent'='trae-agent'; 'Accept'='application/vnd.github+json' }

# 最近运行
Invoke-RestMethod 'https://api.github.com/repos/guokaichong/tauri-codex-ide/actions/runs?per_page=5' -Headers $H

# 某条运行的分步状态（把 RUN_ID 换成上面查到的 id）
Invoke-RestMethod 'https://api.github.com/repos/guokaichong/tauri-codex-ide/actions/runs/<RUN_ID>/jobs' -Headers $H

# 查 Release 产物
(Invoke-RestMethod 'https://api.github.com/repos/guokaichong/tauri-codex-ide/releases/tags/v0.1.0' -Headers $H).assets |
  Select-Object name, size, browser_download_url
```

- 运行页（浏览器）：https://github.com/guokaichong/tauri-codex-ide/actions
- Release 页：https://github.com/guokaichong/tauri-codex-ide/releases

### 4.3 下载安装包（国内网络）

直链（github.com 不通时在前面拼接任一镜像域名，2026-09 实测可用）：

镜像（任选其一，把完整 GitHub 链接接在后面）：

## 5. 发布新版本 SOP（照做即可）

1. **改版本号（两处必须一致）**
   - `package.json` → `"version": "0.2.0"`
   - `src-tauri/tauri.conf.json` → `"version": "0.2.0"`
2. **前端复验**：`npm run build`
3. **提交**：

   ```powershell
   $env:Path='E:\Tools\MinGit\cmd;'+$env:Path
   git add -A
   git -c user.name='guokaichong' -c user.email='2214866337@qq.com' commit -m 'release: v0.2.0'
   ```
4. **同步代码到两端**（main 不会触发构建）：

   ```powershell
   git push github main
   git push https://guokaichong:<Gitee令牌>@gitee.com/guokaichong/tauri-codex-ide.git main
   ```
5. **打标签并推到 GitHub（这一步才触发云端构建）**：

   ```powershell
   git -c user.name='guokaichong' -c user.email='2214866337@qq.com' tag -a v0.2.0 -m 'TauriCodexIDE v0.2.0'
   git push github v0.2.0
   ```
6. 用 4.2 的 API 观察，约 8~15 分钟后 `conclusion=success`，Release 自动出现。
7. 把 Release 链接（必要时附镜像链接）发出即可。

> 标签必须以 `v` 开头；版本号与 tag 保持一致（v0.2.0 ↔ 0.2.0）。
> 只想改代码不发版：只推 main，不要推标签。

## 7. 踩坑全记录（现象 → 原因 → 解决）

### 7.1 git：`CommandNotFoundException` / 找不到 git
- 原因：便携 Git 未加入系统 PATH。
- 解决：每个新终端先 `$env:Path='E:\Tools\MinGit\cmd;'+$env:Path`。

### 7.2 git commit：`Author identity unknown`
- 原因：全局未配置 user.name/email。
- 解决：用 `git -c user.name=... -c user.email=... commit ...` 内联传入，**不修改全局配置**。

### 7.3 git push 卡住无输出 / `Cannot prompt because user interactivity has been disabled`
- 原因：GCM 弹图形登录窗阻塞后台进程；设置 `GIT_TERMINAL_PROMPT=0` 后直接 128 失败。
- 解决：保留 GCM 默认交互；GitHub 首次授权在桌面「Connect to GitHub」窗口点 **Sign in with your browser**。
- 抓 OAuth 链接的方法：设 `$env:GCM_TRACE='<日志路径>'` 后再 push，日志里搜 `login/oauth/authorize`。

### 7.4 Gitee：`Incorrect username or password (access token)`
- 原因：① 用户名填成了邮箱（应为 `guokaichong`）；② 密码位必须填**私人令牌**，登录密码无效。
- 解决：用 3.4 的令牌 URL 推送；先用 OpenAPI `/user?access_token=` 验证令牌。

### 7.5 GitHub OAuth 停在「Confirm access」sudo 页面
- 原因：GitHub 授权新 OAuth App 要求重新输密码（sudo 模式），**只能本人输入，无法绕过**。
- 解决：浏览器里手动输 GitHub 登录密码点 Confirm；完成后 GCM 自动拿到凭据，push 继续。

### 7.6 `github.com` 间歇打不开，但 `api.github.com` 正常
- 现象：浏览器 `ERR_CONNECTION_RESET/TIMED_OUT`；命令行测试 github.com 0/4、api.github.com 4/4。
- 结论：网络对 github.com 的干扰是**间歇性**的，存在持续数分钟的开放窗口；api 域名基本全程可达。
- 对策：
  - 查构建/Release 一律走 `api.github.com`（第 4.2 节），不依赖网页；
  - push 前用 `curl.exe -s -o NUL -w '%{http_code}' --max-time 8 https://github.com` 探测，连续 200 立即推送（仓库仅 0.3MB，几秒推完）；
  - 下载产物用 4.3 的镜像；
  - 本机无代理软件（已确认 7890/7897/10809 等端口均未监听），如以后安装 Clash 类客户端会更稳。

### 7.7 Gitee Go：`[配置结构错误] stages[0].steps 缺失`
- 原因：Gitee Go 2.0 的 YAML 结构（stage 下直接 steps、插件如 `build@nodejs`）与我们写的 jobs/runsOn 结构不兼容；且免费云端无 Windows。
- 解决：放弃 Gitee 构建，删除 `.workflow/` 与 `.gitee/`，统一 GitHub Actions。

### 7.8 PowerShell 5.1 语法/编码坑
- PS 5.1 **不支持** `??`（空合并运算符），轮询脚本里要用 `if/else` 写法。
- git 的中文输出被 PowerShell 当错误流（红色 NativeCommandError 提示），只要 `exit=0` 且看到 `* [new branch/tag]` 即成功。
- 中文 commit message 保持简短，避免引号嵌套；用 `-m '中文说明'`。

### 7.9 推 main 会不会误触发构建？
- 不会。workflow 只在 `v*` 标签和手动 dispatch 时触发；清理类提交可放心推 main。
